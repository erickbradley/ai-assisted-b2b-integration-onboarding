# AWS service mapping - first draft

Status: Draft architecture decision record for the Step 6 service map and first draw.io walkthrough; not a deployment specification or validated implementation.
Date: 2026-10-28

## Context and decision status

The demonstration converts small, manually uploaded support-ticket CSV files into the versioned CRM-shaped Support Case contract. AI proposes mapping rules for human review; a separate executor applies approved rules deterministically. The principal constraints are intermittent use, low maintenance, an interactive experience and a provisional $20/month operating ceiling. Cost feasibility has not been established.

The matrix records Erick's selections for the first draft. **Selected** means chosen for this draft, subject to validation. **Open** means no final implementation choice. **Proposed layout** means a resource grouping suggested for diagram clarity, not an already approved bucket/table design.

Reducing custom transformation-engine development is an explicit selection criterion: reuse an existing engine/library or managed service where practical. Selecting Lambda as a candidate runtime does not mean committing to a transformation engine built from scratch.

## How to read the architecture order

- Numbers indicate the main diagram/request progression. Letters identify related branches at that stage, such as `#7a` and `#7b`; they do not promise concurrent execution.
- DNS resolution, certificate configuration and cross-cutting controls are dependencies, not successive HTTP proxy hops. Route 53 does not carry application requests; ACM does not forward requests.
- Storage rows identify distinct purposes. DynamoDB collections below may share physical tables; table count, keys and indexes are open.
- **Proposed S3 layout:** three buckets: frontend assets, accepted originals, and processing artifacts. Successful results, rejected/review data and staging are separate prefixes within the processing-artifacts bucket. This groups lifecycle/access purposes without asserting that each purpose needs a separate bucket. Physical names remain TBD.
- Private business-data locations are not public origins of the frontend CloudFront distribution. Backend authorization must scope access to the correct workspace and enforce expiration.

| #4 | Cloudflare Turnstile - widget and backend verification integration | Obtain visitor verification evidence and validate it before establishing an interactive session. | Prefer a low-cost verification option over paying for AWS WAF solely for silent Challenge functionality. | **Selected conditionally:** revisit if a material gap or other WAF requirement emerges. The 30-second maximum integration timeout must be reconciled with the synchronous design. Gateway throttling is not a hard financial cap. |
| #6 | AWS Lambda - workflow backend function | Coordinate intake, screening, session/workspace checks, mapping search, inference, review, exact-version authorization and execution requests. | On-demand compute fits intermittent usage and reduces server maintenance. Storing the file does not authorize a run. |
| #7b | Amazon DynamoDB on-demand - approved mapping collection | Store bounded mapping definitions with exact IDs/versions, canonical bindings and searchable metadata. | Keep small rules and metadata together for retrieval and coordinated approval persistence, rather than introduce a separate S3 definition reference. | **Selected.** Query/index design and mapping-size bounds remain open. Shared definitions exclude private source values, prompts, identities and audit history. The canonical schema remains a GitHub/release artifact. |
| #7c | Amazon DynamoDB on-demand - session, review and run-state collection | Persist workspace identity/context, reviewed version, authorization references, request identities, partial-conversion choice and operational run state. | Conditional updates and transactions support coordination even at low traffic, including preventing two copies of one request from claiming separate runs. | **Selected.** Physical table count is open. No expired business values in audit. Approval capture gates execution; final-audit warning policy is described below. |
| #7e | Amazon DynamoDB on-demand - usage and financial-control collection | Track AI attempts, workspace consumption and demo-wide admission/shutdown state. | Authoritative shared counters are needed across requests; browser-only checks cannot enforce spending rules. | **Selected.** Reservation/conditional-update design, numeric quotas, reset periods and financial thresholds remain open. Counters alone do not measure the full AWS bill. |
| #8 | Amazon Bedrock - model inference access | Generate or revise proposed mappings using the canonical contract, source structure, bounded values and user hints. | AWS-managed access fits the chosen platform, Erick has some familiarity, and no requirement currently demands a separate provider API. | **Selected service.** Model, prompt, regional routing, cost and latency remain unvalidated. Only call when the workflow requires inference; reuse skips initial proposal generation. No runtime per-ticket LLM classification or rewriting. |
| #9 | Transformation executor - separate component; AWS Lambda is the candidate runtime | Evaluate a bounded preview or execute an authorized exact mapping version; validate records and produce outcomes. | Separate deterministic execution from mapping decisions and approval authority, with independent permissions/resource controls. | **Open engine choice.** Reuse an existing engine/library versus Lambda coordinating AWS Glue is under review. Lambda remains a candidate, not a commitment to bespoke engine code. Retrieve specified rules; do not select replacements. Preview cannot publish business results. |
| #10a | Amazon S3 - processing-artifacts bucket / successful-results prefix | Store canonical output that represents successful delivery inside the demo and supports review/export. | Retrieve retained business results as private artifacts without placing whole result payloads into coordination metadata. | **Selected S3 use; proposed shared bucket/prefix layout.** Publish only eligible results after validation; partial conversion Off requires zero canonical delivery if any record fails. Exact atomic/publication mechanism remains open. |
| #10b | Amazon S3 - same processing-artifacts bucket / rejected-and-review prefix | Store rejected source records, reasons and temporary record-review artifacts as needed. | Support user-directed correction, recovery and export while keeping payload retention separate from permanent audit metadata. | **Selected S3 use; proposed prefix.** Existing retained originals/results supply before/after values where practical; avoid unnecessary duplicate payloads. NFR-7.4 governs rejected records. Export grouping for otherwise valid records withheld under all-or-nothing remains open. |
| #10c | Amazon S3 - same processing-artifacts bucket / working prefix, if needed | Hold private temporary processing output before publication. | A staging/publication design could separate file creation from successful delivery. | **Proposed option only.** Staging is not an accepted result. Human review occurs after mapping discovery/proposal and before actual execution at #9. The workflow returns to the interface with rules, versions, findings and a bounded preview; both reused and new mappings require fresh confirmation. S3/DynamoDB are accessed throughout the workflow and execution stages, not only once in the numbered order.

## Decisions, alternatives and consequences

| Decision area | First-draft position | Main alternative and tradeoff |
| --- | --- | --- |
| Frontend hosting | S3 + CloudFront + ACM | Amplify Hosting would manage more deployment/hosting setup. The selected approach accepts explicit CDN, certificate and release configuration. |
| Public backend endpoint | API Gateway HTTP API | Function URLs offer a simpler endpoint; REST API offers additional features such as direct WAF integration. No currently identified requirement justifies REST-only features. |
| Human verification | Turnstile, subject to gap review | AWS WAF Challenge provides a silent challenge but introduces WAF and Challenge charges. Human verification does not replace authorization or consumption controls. |
| State and payload storage | S3 + DynamoDB on-demand | S3-only requires more coordination logic; a relational database remains viable if relational constraints, joins or flexible SQL queries become central. DynamoDB is selected for access/update patterns, not a requirement for extreme throughput. |
| Mapping definition storage | Bounded rules and metadata together in DynamoDB | S3 rules plus DynamoDB metadata is viable for larger definitions but adds a cross-service consistency boundary. Validate size and search patterns. |
| Transformation | Separate executor; existing engine preferred | Compare a packaged engine/library in Lambda against managed Glue execution. Do not conflate the runtime with the engine or assume Glue's AI authoring assistance supplies the application's mapping-inference workflow. |
| Inference | Amazon Bedrock | A direct provider API remains an alternative if model quality, availability, features or economics demand it. Choosing Bedrock does not prove a particular model works. |

## Guarantees and validation before implementation

- Approval of the eligible exact reviewed version must be durably captured before actual processing. If that fails, stop before transformation. Preview has its separately bounded authorization (FR-016-018).
- Preserve the record-delivery outcome independently from audit health. If successful result storage is positively confirmed but final audit persistence fails, retain the confirmed results and show the true outcome with an explicit audit warning. Do not label that warning as Partial Success unless records were actually rejected. Audit remains required; repair/notification mechanics are open. Do not rerun transformation to repair an audit write.
- DynamoDB transactions do not include S3 writes. Cross-service publication, all-or-nothing delivery, cleanup and recovery must be explicitly designed; adding both services does not make the run atomic.
- Keep the synchronous workflow-to-executor direction for the current draft. Validate the full browser/API/workflow/executor path, including the HTTP API's 30-second integration ceiling. Bedrock mapping latency must be evaluated separately as well. A gateway timeout is not proof that underlying work stopped; enforce NFR-9.2 rather than silently leave work running.
- Enforce category-specific retention and workspace isolation across originals, result/review artifacts, staging and metadata. The original's 24-hour clock starts at acceptance and does not reset on access or retry. Temporary payload deletion must not erase retained audit metadata (NFR-7.2-7.8).
- Before implementation commitments, estimate idle, expected-use and bounded higher-use monthly costs, plus representative per-workflow cost. Include inference, frontend delivery, builds/deployment tooling, storage, logs, secrets and cleanup where applicable. The $20 ceiling is not the financial shutdown trigger; leave headroom.
- Still open: transformation engine and representation; model/prompt; semantic mapping compatibility search; bucket/table grouping and indexes; exact session/authorizer mechanism; size limits, quotas and timeouts; audit recovery and publication protocol; duplicate-protection and mapping-definition retention durations.
